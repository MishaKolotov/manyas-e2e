# Инструкция «для чайников»: как запускать тесты локализации

Эта инструкция для QA **без опыта автоматизации**. Делай по шагам, команды можно
копировать и вставлять в терминал. Если что-то не получилось — смотри раздел
[«Если что-то пошло не так»](#если-что-то-пошло-не-так).

---

## 0. Что это вообще и зачем

Робот (Playwright) сам проходит онбординг (опросник про ходьбу) на всех языках и
устройствах и проверяет:

- что **переводы есть** и совпадают с гугл-таблицей;
- что на экране **нет «сырых» ключей** вроде `intro_text_0`;
- что **текст не ломает вёрстку** (не вылазит за края);
- и **делает скриншот каждого экрана**, чтобы ты глазами проверил перевод.

Робот **не трогает paywall** — он останавливается, как только тот появляется.

## 1. Установка (один раз)

### 1.1. Поставь Node.js 20

Открой Терминал и проверь:

```bash
node --version
```

Если версия не начинается с `v20`, поставь её. Проще всего через **nvm**:

```bash
# поставить nvm (один раз)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# закрой и открой терминал заново, потом:
nvm install 20
nvm use 20
```

### 1.2. Скачай проект

```bash
git clone <ссылка-на-репозиторий>
cd "Manyas e2e"
```

(Ссылку на репозиторий спроси у команды.)

### 1.3. Установи зависимости и браузеры

```bash
nvm use            # включить Node 20
npm install
npm run install:browsers
```

`install:browsers` качает Chromium и WebKit (~500 МБ) — это нормально, подожди.

### 1.4. Впиши доступы

```bash
cp .env.example .env
```

Открой файл `.env` в любом редакторе и впиши:

```
BASIC_AUTH_USER=dev
BASIC_AUTH_PASS=<ask-the-project-owner>
BASE_URL=https://dev.slimkit.health
```

Файл `.env` в репозиторий не попадёт (он в `.gitignore`) — это правильно.

### 1.5. Загрузи переводы

```bash
npm run i18n:import
```

Эта команда читает файл `WWLI Onboarding Localisation.xlsx` (экспорт гугл-таблицы)
и раскладывает переводы по файлам в `tests/translations/`.

## 2. Запуск тестов

Начни с быстрого прогона только на английском — убедиться, что всё работает:

```bash
npm run test:smoke
```

Полезные команды:

| Что нужно | Команда |
|-----------|---------|
| Быстро, только английский | `npm run test:smoke` |
| Всё: все языки, все устройства, все конфиги | `npm test` |
| Только один конфиг | `TEST_CONFIG=taichiwalking npm test` |
| Один язык + устройство + браузер | `npx playwright test --project=ru__iphone17pro__webkit` |
| Все варианты русского | `npx playwright test --project='/ru__.*/'` |
| Смотреть, как робот кликает (видимый браузер) | `npm run test:headed` |

Имя проекта читается так: `язык__устройство__браузер`.
Языки: `en fr it es ja ru de pt zh ko`.
Устройства: `iphone17pro`, `iphone16promax`, `s20`.
Браузеры: `chromium` (Chrome), `webkit` (Safari).

## 3. Как читать результат

После прогона открой отчёт:

```bash
npm run test:report
```

Откроется страница в браузере:

- **Зелёное** = тест прошёл. **Красное** = упал.
- Кликни на упавший тест — увидишь, на каком шаге и почему.
- У **каждого** теста внизу есть вложения (`attachments`) — это **скриншоты
  каждого экрана** онбординга. Пролистай их и проверь глазами: перевод на месте,
  текст не вылазит, ничего не наезжает.
- У упавших тестов есть ещё `trace` (пошаговая запись) и `video` — помогают понять,
  что произошло.

Если тест упал с сообщением про **`Leaked i18n keys`** — на экране показался
непереведённый ключ (баг приложения).
Если про **`Title anchors not shown with the correct ... translation`** — заголовок
экрана не совпал с переводом из таблицы (баг перевода или приложения).
Если про **`Horizontal overflow`** — текст сломал вёрстку (вылез за край).

**Важно:** красный тест чаще всего означает **баг в приложении/переводе**, а не
поломку теста. Заведи тикет и приложи скриншот из отчёта.

## 4. Частые задачи

### 4.1. Появились новые переводы

1. Экспортируй гугл-таблицу как `.xlsx`.
2. Замени файл `WWLI Onboarding Localisation.xlsx` в корне проекта на новый.
3. Выполни:
   ```bash
   npm run i18n:import
   ```
4. Запусти тесты — упавшие покажут, где приложение ещё не подтянуло новые тексты.

### 4.2. Поменялись ссылки / появился новый конфиг

Открой файл `src/config/configs.ts`. Там список ссылок. Добавь строку по образцу:

```ts
{ name: 'мойконфиг', path: '/walking/survey/', params: 'config=...&stripeV64=true' },
```

`name` — короткое имя (латиницей, без пробелов). `params` — то, что в ссылке после `?`.
Вариант B в A/B-тестах включается автоматически, отдельно дописывать не нужно.

### 4.3. Поменялись устройства

Открой `src/config/devices.ts` — там размеры экранов. Меняй `viewport` при необходимости.

## 5. Если что-то пошло не так

| Симптом | Что делать |
|---------|------------|
| `command not found: npm` | Не установлен Node — вернись к шагу 1.1. |
| `Missing required env vars` | Не заполнен `.env` — шаг 1.4. |
| `Cannot read translations ... Run npm run i18n:import` | Забыл импорт — шаг 1.5. |
| Все тесты падают на первом экране | Возможно, приложение изменилось — позови того, кто правит `OnboardingPage.ts`. |
| Робот «застрял» и дошёл до `MAX_STEPS` | В опроснике появился новый тип экрана — нужна правка `OnboardingPage.ts`. |
| Тест упал, но это реальный баг приложения | Так и должно быть — заведи тикет со скриншотом из отчёта. |

Если непонятно — это нормально. Сложные правки (`OnboardingPage.ts`) делает тот,
кто знаком с кодом; твоя основная работа — **запускать тесты и читать отчёт со
скриншотами**.
